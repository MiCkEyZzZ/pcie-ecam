# 4.4. Чтение и запись

Реализация доступа должна быть одновременно быстрой, безопасной
и переносимой.

## Базовые операции

```rust
impl Ecam {
    fn read32_raw(&self, addr: usize) -> u32 {
        // SAFETY: addr получен из resolve и указывает в окно ECAM
        unsafe { core::ptr::read_volatile(addr as *const u32) }
    }

    fn write32_raw(&self, addr: usize, v: u32) {
        // SAFETY: см. выше
        unsafe { core::ptr::write_volatile(addr as *mut u32, v) }
    }
}
```

## Почему `volatile`

Компилятор не знает, что за адресом находится устройство.
Без `volatile` он может:

- удалить «лишнее» чтение;
- объединить две записи;
- переставить обращения местами.

`volatile` запрещает такие преобразования, но **не** обеспечивает
барьер между разными обращениями.

## Барьеры

| Ситуация | Что нужно |
|----------|-----------|
| Запись конфигурации, затем MMIO | Барьер записи |
| Запись MMIO, затем чтение статуса | Барьер |
| Несколько записей подряд в один регистр | Порядок сохраняется |

```rust
pub fn fence() {
    core::sync::atomic::fence(core::sync::atomic::Ordering::SeqCst);
}
```

## Чтение 16 и 8 бит

Два варианта:

| Вариант | Плюс | Минус |
|---------|------|-------|
| Прямое обращение нужной ширины | Нет побочных эффектов | Требует поддержки платформы |
| Через 32-битное слово | Универсально | Побочные эффекты соседей |

```rust
fn read16_direct(&self, a: Address, off: u16) -> Result<u16, Error> {
    let addr = self.resolve(a, off, 2)?;
    Ok(unsafe { core::ptr::read_volatile(addr as *const u16) })
}
```

Выбор делается один раз при инициализации: если платформа
сообщает, что поддерживает только 32-битные обращения,
используется вариант через слово.

## Запись 16 и 8 бит через слово

```rust
fn write8_via_word(&self, a: Address, off: u16, v: u8) -> Result<(), Error> {
    let aligned = off & !3;
    let shift = (off & 3) * 8;

    let old = self.read32(a, aligned)?;
    let mask = !(0xFFu32 << shift);
    let new = (old & mask) | ((v as u32) << shift);

    self.write32(a, aligned, new)
}
```

Опасность: чтение слова затрагивает соседние байты, которые
могут быть регистрами со побочными эффектами. Поэтому такой
путь применяется только там, где это безопасно, — например,
для BAR и Command.

## Таблица решений

| Регистр | Способ | Почему |
|---------|--------|--------|
| Vendor ID | Прямое чтение 16 | Безопасно |
| BAR | 32 бита | Всегда 32-битный |
| Command | 16 бит | Прямое или через слово |
| MSI-X Table | 32 бита | Требуется атомарность |
| AER Status | 32 бита | `RW1C`, важен точный размер |

## Проверка результата

```rust
let before = cfg.read16(a, 0x04)?;
cfg.write16(a, 0x04, before | 0x0002)?;
let after = cfg.read16(a, 0x04)?;

if after & 0x0002 == 0 {
    return Err(Error::WriteIgnored);
}
```

Проверка полезна при отладке: она сразу показывает, что доступ
не работает или регистр защищён.

## Ошибки доступа

| Симптом | Вероятная причина |
|---------|-------------------|
| Всегда `0xFFFF` | Функции нет или окно не отображено |
| Всегда `0x0000` | Неверный базовый адрес |
| Значения «плывут» | Нет `volatile` или кэширование |
| Зависание | Обращение к отсутствующей функции |
| Ошибка шины | Выход за диапазон окна |

## Производительность

| Операция | Стоимость |
|----------|-----------|
| Чтение конфигурации | Сотни наносекунд |
| Чтение MMIO | Сотни наносекунд |
| Чтение RAM | Единицы наносекунд |

Поэтому перечисление, читающее десятки регистров на каждую
функцию, занимает заметное время. Кэширование идентификаторов
и отказ от лишних чтений заметно ускоряют загрузку.
