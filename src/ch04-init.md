# 4.10. Порядок инициализации

Порядок шагов важен: каждое действие опирается на предыдущее.

## Полная последовательность

```text
 1. Найти описание окон (MCFG или дерево устройств).
 2. Проверить параметры окон.
 3. Отобразить окна в память.
 4. Создать ConfigSpace.
 5. Прочитать идентификаторы корневой шины.
 6. Перечислить шины.
 7. Измерить BAR.
 8. Разместить BAR.
 9. Обновить окна мостов.
10. Включить декодирование.
11. Включить DMA там, где нужно.
12. Настроить прерывания.
13. Передать список устройств дальше.
```

## Код

```rust
pub fn init(desc: &[WindowDesc]) -> Result<HostBridge, Error> {
    let windows = desc.iter()
        .map(EcamWindow::from)
        .collect::<Result<_, _>>()?;

    for w in &windows {
        validate(w)?;
    }

    let cfg = Ecam::new(windows);

    let root = Address { segment: 0, bus: 0, device: 0, function: 0 };
    if cfg.read16(root, 0x00)? == 0xFFFF {
        return Err(Error::NoDevice);
    }

    let mut en = Enumerator::new(&cfg);
    en.run()?;

    let mut alloc = Allocator::new(&cfg, &en.devices);
    alloc.assign_all()?;

    Ok(HostBridge { cfg, devices: en.devices })
}
```

## Почему именно так

| Шаг | Без него |
|-----|----------|
| Проверка окон | Можно испортить память |
| Отображение | Обращения уйдут в пустоту |
| Перечисление | Неизвестно, что настраивать |
| Измерение BAR | Нельзя выделить адреса |
| Окна мостов | Транзакции не дойдут |
| Декодирование | Устройство не отвечает |

## Где может понадобиться повтор

| Случай | Что повторить |
|--------|---------------|
| Сброс шины | Перечисление и размещение |
| Горячее подключение | Только новое поддерево |
| Ошибка конфигурации | Всё, начиная с проверки окон |
| Смена прошивки | Всё целиком |

## Инициализация без прошивки

Если окно известно из констант сборки:

```rust
const ECAM_BASE: usize = 0x4010_0000;
const ECAM_BUSES: core::ops::RangeInclusive<u8> = 0..=0x0F;

let w = EcamWindow {
    base: ECAM_BASE,
    segment: 0,
    start_bus: *ECAM_BUSES.start(),
    end_bus: *ECAM_BUSES.end(),
};
```

Это допустимо на фиксированной плате, но плохо переносится.

## Диагностика

| Симптом | Что проверить |
|---------|---------------|
| `NoDevice` на корне | Отображение, базовый адрес |
| Устройства найдены, но не отвечают | BAR, декодирование, окна мостов |
| Найдена только часть | Диапазон шин |
| Ошибка после сброса | Повторное перечисление |
| Данные «плывут» | Атрибуты памяти, `volatile` |

## Минимальный жизнеспособный вариант

Если времени мало, порядок можно сократить:

```text
1. Окно.
2. Перечисление без распределения.
3. Ручная настройка одного известного устройства.
```

Этого достаточно для проверки доступа, но не для общей системы.

## Завершение

После инициализации драйвер должен:

- не менять номера шин;
- не перераспределять BAR без необходимости;
- сохранять информацию о мостах для горячей замены;
- предоставлять доступ к конфигурации другим модулям.
