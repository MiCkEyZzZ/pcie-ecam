# 7.1. Стенды и эмуляторы

Проверять драйвер удобнее всего на эмуляторе: он
воспроизводим и не требует оборудования.

## QEMU

| Машина | Где ECAM | Особенность |
|--------|----------|-------------|
| `q35` | Стандартная область PCIe | Хорошо эмулирует x86 |
| `virt` (ARM) | Окно в высоких адресах | Узел в дереве устройств |
| `virt` (RISC-V) | То же | Проверка на другой архитектуре |

Запуск с отладочным выводом:

```console
$ qemu-system-aarch64 -M virt -cpu cortex-a57 -m 1G \
    -kernel your_kernel -nographic -d guest_errors
```

## Что видно изнутри

| Проверка | Ожидание |
|----------|----------|
| Vendor ID корневой функции | Не `0xFFFF` |
| Device ID | Известное значение |
| Header Type | `0x00` или `0x01` |
| BAR | Ненулевой размер |

## Сравнение с Linux

На той же машине можно загрузить Linux и посмотреть:

```console
$ lspci -nn
00:00.0 Host bridge [0600]: Intel Corporation 82G33/G31 ...
00:01.0 VGA compatible controller [0300]: ...
00:02.0 Ethernet controller [0200]: ...
```

Адреса должны совпасть с тем, что находит ваш драйвер.

## Юнит-тесты

Логику перечисления можно проверить без оборудования:

```rust
#[test]
fn finds_single_device() {
    let mut fake = FakeConfig::new();
    fake.set(Address::new(0, 0, 1, 0), 0x00, 0x1234);
    fake.set(Address::new(0, 0, 1, 0), 0x02, 0x5678);

    let mut en = Enumerator::new(&fake);
    en.run().unwrap();

    assert_eq!(en.devices.len(), 1);
    assert_eq!(en.devices[0].vendor, 0x1234);
}
```

| Тест | Что проверяет |
|------|---------------|
| Пустая шина | Нет ложных устройств |
| Одно устройство | Базовый обход |
| Мост с двумя шинами | Нумерация |
| Устройство с 8 функциями | Обход функций |
| BAR размером 64 КБ | Измерение |
| Два моста | Порядок номеров |

## Проверка на реальной плате

| Шаг | Инструмент |
|-----|------------|
| Увидеть устройства | `lspci` |
| Увидеть BAR | `lspci -v` |
| Прочитать конфигурацию | `setpci -s 00:01.0 0x00.w` |
| Проверить окна памяти | `cat /proc/iomem` |
| Проверить ошибки | `dmesg`, `lspci -vvv` |

## Отладочный вывод драйвера

```rust
fn dump_device(cfg: &impl ConfigSpace, a: Address) -> Result<(), Error> {
    let vendor = cfg.read16(a, 0x00)?;
    let device = cfg.read16(a, 0x02)?;
    let class = cfg.read32(a, 0x08)?;
    let header = cfg.read8(a, 0x0E)?;

    log::info!(
        "{:04x}:{:02x}:{:02x}.{} {:04x}:{:04x} class {:08x} hdr {:02x}",
        a.segment, a.bus, a.device, a.function, vendor, device, class, header
    );
    Ok(())
}
```

## Сравнение дампов

Полезный приём: снять полный дамп configuration space
эталонным инструментом и своим драйвером, затем сравнить.

```console
$ lspci -xxx > ref.txt
```

Расхождение в первых 64 байтах означает ошибку адресации,
а не ошибку устройства.

## Нагрузочные проверки

| Проверка | Цель |
|----------|------|
| Много устройств | Стек обхода, лимиты |
| Глубокое дерево | Нумерация шин |
| Отсутствующие функции | Обработка `0xFFFF` |
| Сброс шины | Повторное перечисление |

## Что считать успехом

- Все устройства видны и совпадают с эталоном.
- BAR распределены без пересечений.
- MMIO устройства читается и пишется.
- Прерывания приходят.
- Повторная инициализация не ломает состояние.
