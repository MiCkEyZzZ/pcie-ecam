# 4.6. Требования к безопасности

Работа с ECAM — это `unsafe`-код, потому что адрес приходит
из конфигурации, а за ним находится устройство, а не память.

## Границы недоверия

| Источник | Что может быть не так |
|----------|-----------------------|
| Таблица MCFG | Битый адрес, перекрытие с RAM |
| Дерево устройств | Неверный `reg`, отсутствие `bus-range` |
| Параметры сборки | Опечатка в базовом адресе |
| Само устройство | Возвращает любые значения |

## Правила

| Правило | Почему |
|---------|--------|
| Проверять диапазон до вычисления адреса | Иначе можно обратиться к RAM |
| Проверять выравнивание | Иначе ошибка шины |
| Не выходить за 4 КБ функции | Иначе чужая функция |
| Помечать окно как `Device` | Иначе кэш исказит данные |
| Использовать `read_volatile` | Иначе компилятор уберёт обращение |

## Проверка окна при инициализации

```rust
fn validate(w: &EcamWindow) -> Result<(), Error> {
    if w.base % 0x1000 != 0 {
        return Err(Error::Misaligned);
    }
    if w.start_bus > w.end_bus {
        return Err(Error::BadAddress);
    }
    let size = ((w.end_bus as usize) - (w.start_bus as usize) + 1) << 20;
    let end = w.base.checked_add(size).ok_or(Error::Overflow)?;

    if overlaps_ram(w.base, end) {
        return Err(Error::Forbidden);
    }
    Ok(())
}
```

## Почему проверка перекрытия с RAM обязательна

Если окно ECAM по ошибке указывает на обычную память, то:

- чтение вернёт содержимое памяти, а не конфигурацию;
- запись испортит данные;
- ошибки будут выглядеть как «устройство с странным ID».

Проверка на пересечение с картой памяти выполняется один раз
при инициализации.

## Атрибуты страниц

| Атрибут | Значение | Почему |
|---------|----------|--------|
| Кэширование | Запрещено | Данные меняются без участия CPU |
| Буферизация записи | Запрещена или с барьерами | Порядок важен |
| Исполнение | Запрещено | Это не код |
| Совместный доступ | Разрешён | Многоядерные системы |

## Инварианты

Драйвер должен поддерживать:

```text
1. Любой EcamWindow либо корректен, либо отвергнут при создании.
2. resolve() либо возвращает адрес внутри окна, либо ошибку.
3. Ни одно чтение/запись не выходит за 4 КБ функции.
4. Базовый адрес не меняется после инициализации.
```

## Типы-обёртки

```rust
pub struct MmioAddr(usize);

impl MmioAddr {
    pub fn new(addr: usize) -> Self { Self(addr) }
    pub fn get(self) -> usize { self.0 }
}
```

Обёртка не даёт случайно сложить адрес с размером и получить
что-то осмысленное.

## Работа с `unsafe`

```rust
/// # Safety
/// `addr` должен указывать в отображённое окно ECAM
/// и быть выровнен на 4 байта.
unsafe fn read32_unchecked(addr: usize) -> u32 {
    core::ptr::read_volatile(addr as *const u32)
}
```

Каждая `unsafe`-функция документирует свои требования, а
безопасная обёртка проверяет их перед вызовом.

## Многопоточность

| Риск | Мера |
|------|------|
| Гонка при записи BAR | Блокировка на время изменения |
| Гонка при перечислении | Один поток-инициатор |
| Чтение во время записи | Атомарные операции там, где нужно |

Configuration space не поддерживает транзакций: две записи
в соседние регистры могут быть перемешаны. Поэтому изменения
конфигурации устройства выполняются под блокировкой.

## Что запрещено

| Действие | Почему |
|----------|--------|
| Вычислять адрес в `usize` без проверки переполнения | Может дать адрес в RAM |
| Кэшировать указатель на функцию | Смещения фиксированы, но база может измениться при переинициализации |
| Писать в BAR без сохранения оригинала | Нельзя восстановить состояние |
| Сканировать шины вне диапазона | Возможны зависания |
