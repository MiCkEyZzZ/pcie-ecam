# 5.1. ACPI и MCFG

На платформах с ACPI окно ECAM описывается таблицей MCFG.

## Путь получения

```text
RSDP → XSDT → таблица с сигнатурой MCFG → записи окон
```

| Шаг | Что делаем |
|-----|------------|
| 1 | Найти `RSDP` (в памяти или через UEFI) |
| 2 | Проверить контрольную сумму |
| 3 | Взять `XSDT` (или `RSDT` для 32-бит) |
| 4 | Пройти таблицы, найти `MCFG` |
| 5 | Проверить длину и контрольную сумму |
| 6 | Разобрать записи |

## Разбор

```rust
pub fn read_mcfg(table: &[u8]) -> Result<HeaplessVec<McfgEntry, 8>, Error> {
    if table.len() < 0x2C || &table[0..4] != b"MCFG" {
        return Err(Error::BadAddress);
    }

    let len = u32::from_le_bytes(table[4..8].try_into().unwrap()) as usize;
    if len > table.len() || len < 0x2C {
        return Err(Error::BadAddress);
    }

    let mut out = HeaplessVec::new();

    for chunk in table[0x2C..len].chunks_exact(16) {
        let base = u64::from_le_bytes(chunk[0..8].try_into().unwrap());
        let segment = u16::from_le_bytes(chunk[8..10].try_into().unwrap());
        let start = chunk[10];
        let end = chunk[11];

        if start > end {
            continue;
        }
        out.push(McfgEntry { base, segment, start, end })?;
    }
    Ok(out)
}
```

## Что проверять

| Проверка | Причина |
|----------|---------|
| Сигнатура | Таблица может быть другого типа |
| Длина | Обрезанные данные |
| Кратность 16 | Иначе последняя запись неполная |
| `start <= end` | Иначе диапазон пуст |
| Выравнивание базы | Требование ECAM |
| Пересечение окон | Неоднозначность |

## Несколько окон

```text
MCFG
 ├── segment 0, bus 0x00–0x3F, base 0xE0000000
 └── segment 0, bus 0x40–0x7F, base 0xE4000000
```

Это нормальная конфигурация: окно описано дважды, потому что
диапазон шин разбит. Драйвер должен выбрать окно по номеру шины,
а не только по сегменту.

## Если ACPI есть, а MCFG нет

| Вариант | Что делать |
|---------|------------|
| Старая система | Использовать доступ через порты |
| Ошибка прошивки | Сообщить и не пытаться угадать |
| Гибридная система | Проверить дерево устройств |

## Альтернатива: UEFI

Загрузчик может получить окно через `EFI_PCI_ROOT_BRIDGE_IO_PROTOCOL`
или передать уже готовое описание. В этом случае ACPI может
не понадобиться вовсе.

## Память таблиц

| Свойство | Значение |
|----------|----------|
| Время жизни | До перезагрузки |
| Изменяемость | Нет |
| Доступ | Только чтение |
| Отображение | Обычно уже доступно |

Копировать таблицу не нужно: достаточно сохранить разобранные
записи.

## Ошибки

| Код | Причина |
|-----|---------|
| `BadAddress` | Битая сигнатура или длина |
| `Overflow` | Адрес окна плюс размер не помещается |
| `Forbidden` | Окно пересекается с RAM |

## Практика

На QEMU MCFG можно посмотреть так:

```console
$ acpidump > dump.bin
$ acpixtract -a dump.bin
$ iasl -d mcfg.dat
```

В дампе будут видны записи с базой, сегментом и диапазоном шин.
Это самый быстрый способ проверить, что драйвер видит те же
значения, что и прошивка.
