# 2.9. Распределение ресурсов

Перечисление отвечает на вопрос «что есть», распределение —
«где это будет лежать в адресном пространстве».

## Что нужно выделить

| Ресурс | Кому | Источник |
|--------|------|----------|
| Память MMIO | BAR функций | Окно памяти корневого комплекса |
| Ввод-вывод | BAR функций (редко) | Окно ввода-вывода |
| Номера шин | Мостам | Свободные номера сегмента |
| Прерывания | Функциям | Контроллер прерываний или MSI |

## Определение размера BAR

Классический приём:

```text
1. Прочитать исходное значение BAR.
2. Записать все единицы (0xFFFF_FFFF).
3. Прочитать значение обратно.
4. Инвертировать — получится маска размера.
5. Восстановить исходное значение.
```

Пример:

| Шаг | BAR0 |
|-----|------|
| Исходно | `0xFEBC0004` |
| Записано | `0xFFFFFFFF` |
| Прочитано | `0xFFF00000` |
| Инверсия | `0x000FFFFF` |
| Размер | 1 МБ |

Младшие биты маски — нули, потому что они заняты признаками
типа и prefetchable.

## Типы BAR

| Бит 0 | Тип | Как читать размер |
|-------|-----|-------------------|
| 0 | Память | Маска по битам 4+ |
| 1 | Ввод-вывод | Маска по битам 2+ |

Для памяти биты 2:1 задают разрядность:

| Бит 2:1 | Значение |
|---------|----------|
| `0b00` | 32-битный адрес |
| `0b10` | 64-битный адрес |
| `0b01` | Зарезервировано |
| `0b11` | Зарезервировано |

64-битный BAR занимает два соседних слота: младшее слово
и старшее. При распределении это нужно учитывать.

## Выравнивание

Адрес BAR должен быть выровнен на его размер:

```text
addr % size == 0
```

Для окна 1 МБ подходят адреса `0x...00000`, `0x...100000`
и так далее.

## Порядок распределения

| Шаг | Действие |
|-----|----------|
| 1 | Собрать все запросы (размер, тип) |
| 2 | Отсортировать по убыванию размера |
| 3 | Выделить адреса из окон с учётом выравнивания |
| 4 | Записать адреса в BAR |
| 5 | Включить декодирование в Command |

Сортировка по убыванию уменьшает фрагментацию.

## Окна моста

Мост тоже имеет окна: `Memory Base/Limit`,
`Prefetchable Base/Limit`, `IO Base/Limit`. Они должны покрывать
все ресурсы устройств за мостом.

```text
Мост
 ├── Memory Base  = min(адресов потомков)
 └── Memory Limit = max(адресов потомков)
```

Если окно не покрывает адрес, транзакция к устройству
не пройдёт через мост.

## Включение декодирования

| Бит Command | Что разрешает |
|-------------|---------------|
| 0 | Реакцию на обращения к вводу-выводу |
| 1 | Реакцию на обращения к памяти |
| 2 | Bus master (DMA) |

Порядок: сначала записать BAR, затем включить декодирование.
Обратный порядок приведёт к обращению по неверному адресу.

## Барьеры

После записи BAR и Command нужен барьер, прежде чем обращаться
к MMIO устройства:

```rust
// запись конфигурации
cfg.write32(addr, 0x10, bar)?;
cfg.write16(addr, 0x04, cmd | 0x2)?;

// гарантировать завершение записи до MMIO
fence();
```

## Что делать при нехватке места

| Ситуация | Решение |
|----------|---------|
| Окно меньше суммы BAR | Не включать часть устройств |
| Нет выравнивания | Расширить окно или переразместить |
| Конфликт с RAM | Ошибка конфигурации, не пытаться «подвинуть» |

## Итог

Распределение должно быть детерминированным: одинаковый набор
устройств при одинаковой конфигурации обязан давать одинаковые
адреса. Это важно для воспроизводимости и для отладки.
