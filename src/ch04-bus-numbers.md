# 4.8. Нумерация шин

Номера шин не заданы заранее: их назначает драйвер при обходе.

## Правила

| Правило | Пояснение |
|---------|-----------|
| Корневая шина обычно 0 | Задаётся платформой |
| Каждый мост получает следующий номер | По порядку обхода |
| Поддерево занимает непрерывный диапазон | Требование маршрутизации |
| Номера не повторяются в сегменте | Иначе неоднозначность |

## Выделение

```rust
pub struct BusAllocator {
    next: u8,
    end: u8,
}

impl BusAllocator {
    pub fn alloc(&mut self) -> Result<u8, Error> {
        if self.next > self.end {
            return Err(Error::NoResources);
        }
        let b = self.next;
        self.next += 1;
        Ok(b)
    }

    pub fn highest_used(&self) -> u8 {
        self.next.saturating_sub(1)
    }
}
```

## Пример

Исходно: `next = 1`, `end = 8`.

```text
bus 0
 ├── dev 1 (мост) → получает bus 1
 │     ├── dev 0
 │     └── dev 3 (мост) → получает bus 2
 │           └── dev 0
 ├── dev 2 (мост) → получает bus 3
 └── dev 4
```

После обхода:

| Мост | Primary | Secondary | Subordinate |
|------|---------|-----------|-------------|
| dev 1 | 0 | 1 | 2 |
| dev 3 на bus 1 | 1 | 2 | 2 |
| dev 2 | 0 | 3 | 3 |

## Запись subordinate

Пока идёт обход поддерева, мост должен пропускать все шины
под ним. Поэтому:

```text
1. secondary = новый номер
2. subordinate = 0xFF (временно) или новый номер
3. обход
4. subordinate = фактический максимум
```

Вариант с `0xFF` проще, но делает мост слишком «широким»:
он будет отвечать на транзакции к шинам, которых нет.

## Проверка диапазона

```rust
if bus < start_bus || bus > end_bus {
    return Err(Error::BusOutOfRange);
}
```

Диапазон берётся из MCFG или `bus-range`. Сканирование за его
пределами может привести к зависанию.

## Сброс шины

Бит 6 в `Bridge Control` сбрасывает вторичную шину:

```rust
let ctrl = cfg.read16(bridge, 0x3E)?;
cfg.write16(bridge, 0x3E, ctrl | 0x0040)?;
delay_ms(1);
cfg.write16(bridge, 0x3E, ctrl & !0x0040)?;
```

После сброса поддерево нужно перечислить заново: BAR устройств
обнулятся.

## Нумерация и ACPI

Прошивка может заранее назначить номера шин. В этом случае
драйвер не должен их менять:

| Источник | Что делать |
|----------|------------|
| MCFG + описанная топология | Использовать готовые номера |
| Чистое перечисление | Назначать самостоятельно |
| Смешанный случай | Не трогать мосты с ненулевым `secondary` |

Проверка:

```rust
let sec = cfg.read8(bridge, 0x19)?;
if sec != 0 {
    // номер уже назначен — использовать его
}
```

## Ошибки нумерации

| Ошибка | Симптом |
|--------|---------|
| Повтор номера | Устройства видны не там |
| Разрыв диапазона | Часть дерева недоступна |
| `subordinate` меньше нужного | Устройства за мостом не отвечают |
| `subordinate` больше нужного | Мост перехватывает чужие адреса |
| Номер вне диапазона окна | Обращение уходит в пустоту |

## Ограничение количества шин

| Причина | Следствие |
|---------|-----------|
| Окно меньше 256 МБ | Не все номера доступны |
| Ограничение прошивки | Диапазон уже |
| Много мостов | Номера заканчиваются |

При исчерпании номеров оставшиеся мосты не перечисляются,
а в лог пишется ошибка `NoResources`.
