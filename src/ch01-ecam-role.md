# 1.2. Место ECAM в топологии PCIe

Configuration space в PCIe доступно двумя способами.

| Способ | Как работает | Применение |
|--------|--------------|------------|
| ECAM | Окно памяти, отображённое на все шины | Современные системы |
| Механизм #1 / #2 | Порты `0xCF8`/`0xCFC` или `0xC000` | Устаревшие x86-системы |

ECAM — основной способ. Он описан в базовой спецификации PCIe
и обязателен для корневых комплексов; устаревший доступ через
порты сохранён только для совместимости со старым программным
обеспечением.

## Как это выглядит в адресном пространстве

```text
Физическая память
 ┌─────────────────────────────────────────┐
 │ ...                                     │
 ├─────────────────────────────────────────┤
 │ Окно ECAM                               │
 │  bus 0  ─ 32 устройства × 8 функций     │
 │  bus 1                                  │
 │  ...                                    │
 ├─────────────────────────────────────────┤
 │ Окна MMIO устройств                     │
 ├─────────────────────────────────────────┤
 │ ...                                     │
 └─────────────────────────────────────────┘
```

## Почему окно, а не транзакции

Configuration-транзакции PCIe адресуются полем `Bus/Device/Function`
в заголовке TLP. Чтобы процессор мог их формировать, нужен
специальный контроллер. Вместо этого спецификация предлагает
отобразить конфигурацию в память: тогда обращение к памяти
превращается в configuration-транзакцию аппаратно.

Это даёт:

- обычные load/store вместо специальных инструкций;
- доступ к расширенному пространству до 4 КБ на функцию;
- единый механизм для всех архитектур.

## Что находится за окном

| Диапазон смещения | Содержимое |
|-------------------|------------|
| `0x000`–`0x0FF` | Стандартное пространство PCI |
| `0x100`–`0xFFF` | Расширенное пространство PCIe |

Стандартные 256 байт совпадают по раскладке с PCI, поэтому
драйверы, написанные для PCI, работают и здесь.

## Ограничения

- Окно описывает **все** шины сегмента, включая несуществующие.
  Обращение к отсутствующей функции может привести к ошибке шины.
- Адресация каждой функции фиксирована, поэтому размер окна
  определяется диапазоном номеров шин.
- Запись в окно не является атомарной операцией над несколькими
  регистрами.

## Связь с ACPI и деревом устройств

Прошивка сообщает:

- **базовый адрес** окна;
- **диапазон шин**, который окно покрывает;
- **номер сегмента**, к которому относятся эти шины.

В ACPI это таблица MCFG, в дереве устройств — свойства узла
`pci-host-ecam-generic`. Драйвер не должен угадывать адрес.
