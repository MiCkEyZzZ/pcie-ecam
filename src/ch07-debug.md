# 7.2. Типичные ошибки

Ниже — список проблем, которые встречаются чаще всего,
с признаками и способами проверки.

## Ошибки адресации

| Симптом | Причина | Проверка |
|---------|---------|----------|
| Все ID `0xFFFF` | Неверный базовый адрес | Сравнить с MCFG |
| Устройства «сдвинуты» | Не учтён `start_bus` | Прочитать `bus-range` |
| Видны чужие устройства | Окно перекрывает соседнее | Сравнить диапазоны |
| Зависание при обходе | Сканирование вне диапазона | Ограничить `end_bus` |

## Ошибки разрядности

```text
Платформа поддерживает только 32-битные обращения,
драйвер пишет байтами → данные не доходят.
```

Проверка: записать `0xAA` в байтовый регистр и прочитать
словом — если байт не изменился, прямой доступ не работает.

## Ошибки BAR

| Симптом | Причина |
|---------|---------|
| Устройство молчит | BAR не записан или не включено декодирование |
| Значение BAR не меняется | Окно только для чтения |
| Размер определён неверно | Не учтён 64-битный BAR |
| Второй BAR испорчен | 64-битный BAR занял два слота |
| Конфликт адресов | Нет проверки пересечений |

## Ошибки мостов

| Симптом | Причина |
|---------|---------|
| Устройства за мостом не видны | `secondary` не назначен |
| Видна только часть | `subordinate` слишком мал |
| Мост отвечает за других | `subordinate` слишком велик |
| После сброса ничего нет | Не повторено перечисление |

## Ошибки памяти

| Симптом | Причина |
|---------|---------|
| Значения «залипают» | Кэширование окна |
| Запись не доходит | Нет барьера |
| Случайные сбои | Нет `volatile` |
| Порча данных | Окно пересекает RAM |

## Ошибки перечисления

| Симптом | Причина |
|---------|---------|
| Устройство с 8 функциями видно как одно | Не проверен бит multi-function |
| Функции 1–7 не видны | Обход только функции 0 |
| Дубли устройств | Повторный обход без очистки списка |
| Бесконечный цикл | Петля в дереве мостов |

## Диагностический чек-лист

```text
1. Правильный ли базовый адрес?
2. Правильный ли диапазон шин?
3. Читается ли vendor ID корневой функции?
4. Совпадает ли header type с ожидаемым?
5. Записывается ли BAR?
6. Включено ли декодирование памяти?
7. Покрывает ли окно моста адрес устройства?
8. Есть ли барьер перед MMIO?
9. Не кэшируется ли окно?
10. Не пересекается ли окно с RAM?
```

## Инструменты

| Инструмент | Что показывает |
|------------|----------------|
| `lspci -vvv -xxx` | Полный дамп конфигурации |
| `setpci` | Точечное чтение и запись |
| `/proc/iomem` | Занятые диапазоны |
| `dmesg` | Ошибки драйвера и шины |
| Логический анализатор | Реальные транзакции на линии |

## Приём: минимальный тест

Если непонятно, где ошибка, свести задачу к минимуму:

```text
1. Отобразить окно.
2. Прочитать только vendor ID корневой функции.
3. Сравнить с эталоном.
```

Если это работает — проблема в перечислении или ресурсах.
Если нет — в адресации или отображении.

## Приём: сравнение с эталоном

```console
$ lspci -xxx -s 00:01.0 > a.txt
$ ./mydump 00:01.0        > b.txt
$ diff <(head -4 a.txt) <(head -4 b.txt)
```

Первые 16 байт содержат идентификаторы и команду — они должны
совпасть.

## Ошибки, которых лучше не допускать

| Ошибка | Последствие |
|--------|-------------|
| Писать в BAR без сохранения | Нельзя восстановить состояние |
| Сканировать все 256 шин | Зависание на пустой шине |
| Включать bus master всем | Устройство может испортить память |
| Игнорировать ошибки чтения | Дальнейшая работа с мусором |
| Менять номера шин, заданные прошивкой | Ломается описанная топология |

## Итог

Большинство проблем сводится к трём вопросам:

1. **Туда ли** идёт обращение?
2. **Тот ли** размер и выравнивание?
3. **Тот ли** момент — до или после включения декодирования?

Если ответы на них подтверждены, оставшиеся ошибки почти всегда
связаны с конкретным кремнием.
