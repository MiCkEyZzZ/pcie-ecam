# 2.10. Маршрутизация configuration-запросов

ECAM меняет только способ доступа. Сами запросы к конфигурации
подчиняются правилам маршрутизации PCIe, и их полезно понимать,
иначе ошибки перечисления выглядят необъяснимо.

## Два типа запросов

| Тип | Кому адресован | Что содержит |
|-----|----------------|--------------|
| Type 0 | Устройству на текущей шине | Номер устройства и функции |
| Type 1 | Мосту, за которым нужная шина | Номер шины, устройства и функции |

Различие принципиальное: Type 0 не проходит через мосты, Type 1
проходит, пока номер шины попадает в диапазон моста.

## Что делает корневой комплекс

При обращении к окну ECAM контроллер:

```text
1. Выделяет из адреса bus/device/function/offset.
2. Если bus == номер корневой шины — формирует Type 0.
3. Иначе — формирует Type 1 и отправляет в сторону шины.
```

## Что делает мост

| Условие | Действие |
|---------|----------|
| `bus` вне `secondary..=subordinate` | Запрос не принадлежит поддереву, мост его не принимает |
| `bus == secondary` | Преобразует Type 1 в Type 0 и передаёт на вторичную шину |
| `secondary < bus <= subordinate` | Передаёт Type 1 дальше без преобразования |

## Диапазон шин как фильтр

Именно поэтому `Subordinate Bus Number` должен быть не меньше
всех номеров поддерева. Если значение меньше, запрос к дальней
шине не попадёт в диапазон, и мост ответит отказом.

```text
мост: secondary = 1, subordinate = 1
запрос к bus 2 → вне диапазона → отказ
запрос к bus 1 → Type 0 на вторичную шину
```

Обратная ошибка — слишком большой `subordinate` — приводит к тому,
что мост перехватывает запросы к шинам, которые ему не принадлежат.

## Что видит программное обеспечение

| Ситуация | Наблюдение через ECAM |
|----------|-----------------------|
| Устройства нет | `0xFFFF` в Vendor ID |
| Мост не пропускает | `0xFFFF` или ошибка шины |
| Нет устройства 0 на шине | Запросы к остальным устройствам могут не работать |
| Обращение вне окна | Ошибка шины или мусор |

## Правило устройства 0

На шине за мостом обычно присутствует устройство 0: это либо
сам мост (для корневого порта), либо первое устройство слота.
Некоторые реализации требуют, чтобы device 0 function 0
существовал, прежде чем станут доступны остальные устройства
шины.

Практический вывод: перечисление всегда начинается с device 0,
а не с первого «интересного» устройства.

## Отказы и их обработка

| Ответ | Значение |
|-------|----------|
| Unsupported Request (UR) | Адресат не принял запрос |
| Completion Timeout | Ответ не пришёл |
| Master Abort (в PCI) | Нет устройства по адресу |

В PCIe отказ обычно возвращается как завершение с признаком UR,
а не как зависание. Но не все контроллеры ECAM корректно
преобразуют это в ошибку чтения — часть возвращает `0xFFFFFFFF`.

## Границы применимости

| Ограничение | Следствие |
|-------------|-----------|
| Type 0 не выходит за шину | Нельзя «достать» устройство за мостом одним запросом |
| Диапазон шин обязателен | Без него мост не знает, что пропускать |
| Номера шин назначаются | До назначения адреса не определены |
| Запросы не транзакционны | Нельзя атомарно изменить два регистра |

## Связь с ECAM

```text
адрес памяти
    │
    ▼
контроллер ECAM
    │  выбирает тип запроса по номеру шины
    ▼
шина PCIe ──▶ мост ──▶ шина ──▶ устройство
    ▲                              │
    └──────── completion ──────────┘
```

Окно ECAM — это представление результата. Ошибки маршрутизации
проявляются как ошибки доступа к памяти, а не как ошибки
конфигурации.
