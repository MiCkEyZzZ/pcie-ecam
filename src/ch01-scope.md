# 1.4. Границы применимости

ECAM — не универсальное решение. Есть ситуации, где он
не применяется или применяется с оговорками.

## Когда ECAM не подходит

| Ситуация | Причина |
|----------|---------|
| Устройство за мостом PCI (не PCIe) | Configuration-транзакции не проходят через PCI-мост в таком виде |
| Старая x86-система без MCFG | Доступ только через порты `0xCF8`/`0xCFC` |
| Отсутствие отображения памяти | Окно не описано прошивкой |
| Ограничение на размер окна | Диапазон шин уже, чем всё дерево |

## Ограничения стандартного пространства

Стандартные 256 байт достаточны, чтобы найти BAR и список
возможностей, но не содержат:

- регистров AER;
- MSI-X таблицы (только указатель);
- серийного номера устройства;
- параметров виртуализации SR-IOV.

Для них нужно расширенное пространство, а значит — полноценные
4 КБ на функцию.

## Ограничения платформы

| Ограничение | Следствие |
|-------------|-----------|
| Только 32-битные обращения | Нельзя использовать байтовые операции |
| Частичное декодирование адреса | Некоторые функции недоступны |
| Отсутствие таймаута | Обращение к пустой функции может подвесить шину |
| Кэшируемое окно | Нужны явные барьеры и запрет кэша |

## Что считать «отсутствующим устройством»

Чтение vendor ID даёт `0xFFFF`, если функции нет. Но:

- некоторые платформы возвращают `0xFFFFFFFF` на любое обращение
  за пределы окна;
- некоторые возвращают мусор;
- некоторые генерируют ошибку шины.

Поэтому первое чтение всегда должно быть защищённым: либо
аппаратным таймаутом, либо известным диапазоном шин из прошивки.

## Совместимость с PCI

Устройства PCI, подключённые через PCIe-мост, видны в ECAM.
Их configuration space — те же 256 байт, но расширенное
пространство для них не определено.

## Итог

Драйвер должен:

1. брать диапазон шин из прошивки, а не сканировать всё;
2. проверять выравнивание и разрядность;
3. уметь работать только с 32-битными обращениями;
4. не считать, что любое чтение за пределами окна безопасно.
