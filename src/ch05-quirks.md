# 5.3. Особенности реализаций

Спецификация описывает поведение, но кремний бывает строже
или снисходительнее. Ниже — типичные отклонения.

## Доступ только по 32 бита

Многие контроллеры не поддерживают байтовые и полусловные
обращения к ECAM.

| Реализация | Поддержка |
|------------|-----------|
| Полная | 8, 16, 32 |
| Типичная | 32 |
| Строгая | 32, выровненные |

Решение: реализовать `read8`/`read16` через 32-битное слово
с маской. Ограничение: побочные эффекты соседних регистров.

## Отсутствие таймаута

Если контроллер не сообщает об ошибке при обращении к пустой
функции, шина может подвиснуть.

| Мера | Эффект |
|------|--------|
| Ограничить диапазон шин | Не выходить в пустоту |
| Сканировать только известные слоты | Меньше риска |
| Использовать `bus-range` из прошивки | То же |

## Возврат мусора

Некоторые платформы возвращают не `0xFFFF`, а произвольные
значения для отсутствующих функций.

```rust
fn looks_absent(vendor: u16, device: u16) -> bool {
    vendor == 0xFFFF || vendor == 0x0000 || vendor == 0x0001
        || device == 0xFFFF || device == 0x0000
}
```

Проверка эвристическая: реальные устройства с vendor `0x0001`
не встречаются, но правило всё равно стоит держать в одном месте.

## Окно начинается не с шины 0

```text
ECAM_BASE соответствует bus 0x40, а не 0x00
```

Тогда смещение считается от `start_bus`. Ошибка в этом месте
даёт «устройства есть, но не те».

## Несколько функций на устройстве

Признак multi-function может быть выставлен некорректно.
Надёжнее проверять vendor ID каждой функции, а не доверять
биту 7:

```rust
for fn in 0..8 {
    if cfg.read16(a.with_function(fn), 0x00)? != 0xFFFF {
        probe(a.with_function(fn))?;
    }
}
```

## Барьеры и порядок

| Платформа | Особенность |
|-----------|-------------|
| Слабая модель памяти | Нужны явные барьеры |
| Сильная модель | Барьеры не обязательны, но не вредят |
| Отложенные записи | Барьер перед MMIO обязателен |

## Кэширование окна

Если окно случайно отображено с кэшированием:

- чтение вернёт старое значение;
- запись может не дойти;
- проявятся «случайные» ошибки при перечислении.

Проверка: прочитать BAR, записать новое значение, прочитать
снова. Если вернулось старое — почти наверняка кэш.

## Устройства, меняющие состояние при чтении

| Регистр | Эффект |
|---------|--------|
| AER Status | Очистка при чтении |
| MSI-X Pending | Может меняться |
| PME Status | Очистка |

При перечислении такие регистры не трогают.

## Сброс шины

Некоторые хабы после сброса требуют паузу перед первым
обращением:

```rust
reset_secondary(bridge)?;
delay_ms(100);
scan_bus(secondary)?;
```

Без паузы устройства могут не успеть выйти на шину.

## Таблица отклонений

| Симптом | Вероятная особенность |
|---------|----------------------|
| Данные не пишутся | Только 32-битный доступ |
| Устройство не видно | Окно сдвинуто по шинам |
| Видны «лишние» функции | Ложный multi-function |
| Зависание при обходе | Нет таймаута |
| Старые значения | Кэширование |
