# 2.4. Таблица MCFG

ACPI описывает окна ECAM таблицей **MCFG** (Memory Mapped
Configuration Space).

## Где она находится

| Свойство | Значение |
|----------|----------|
| Сигнатура | `MCFG` |
| Размещение | В таблицах ACPI, обычно в `XSDT` |
| Область | Статическая, только чтение |

## Заголовок таблицы

| Смещение | Поле | Размер |
|----------|------|--------|
| `0x00` | Сигнатура `MCFG` | 4 |
| `0x04` | Длина таблицы | 4 |
| `0x08` | Ревизия | 1 |
| `0x09` | Контрольная сумма | 1 |
| `0x0A` | OEM ID | 6 |
| `0x10` | OEM Table ID | 8 |
| `0x18` | OEM Revision | 4 |
| `0x1C` | Creator ID | 4 |
| `0x20` | Creator Revision | 4 |
| `0x24` | Зарезервировано | 8 |
| `0x2C` | Первая запись | — |

## Запись описания окна

| Смещение | Поле | Размер | Смысл |
|----------|------|--------|-------|
| `0x00` | Base Address | 8 | Физический адрес окна |
| `0x08` | Segment Group | 2 | Номер сегмента |
| `0x0A` | Start Bus | 1 | Первая шина |
| `0x0B` | End Bus | 1 | Последняя шина |
| `0x0C` | Reserved | 4 | Нули |

Записи идут подряд, их количество вычисляется как
`(length - 0x2C) / 16`.

## Пример разбора

```rust
pub struct McfgEntry {
    pub base: u64,
    pub segment: u16,
    pub start_bus: u8,
    pub end_bus: u8,
}

pub fn parse_mcfg(table: &[u8]) -> impl Iterator<Item = McfgEntry> + '_ {
    let mut off = 0x2C;
    core::iter::from_fn(move || {
        if off + 16 > table.len() { return None; }
        let base = u64::from_le_bytes(table[off..off + 8].try_into().unwrap());
        let segment = u16::from_le_bytes(table[off + 8..off + 10].try_into().unwrap());
        let start_bus = table[off + 10];
        let end_bus = table[off + 11];
        off += 16;
        Some(McfgEntry { base, segment, start_bus, end_bus })
    })
}
```

## На что обращать внимание

| Проверка | Зачем |
|----------|-------|
| Длина таблицы кратна 16 после заголовка | Защита от обрезанных таблиц |
| `start_bus <= end_bus` | Иначе диапазон пуст |
| База выровнена на 4 КБ | Требование ECAM |
| База не пересекается с RAM | Иначе память будет испорчена |
| Сегменты не перекрываются | Один адрес не должен принадлежать двум окнам |

## Несколько записей

В системе может быть несколько окон: например, отдельные
для встроенных устройств и для слотов. Каждое окно описывается
своей записью со своим сегментом.

```text
MCFG
 ├── запись: segment 0, bus 0x00–0x3F, base 0xE000_0000
 ├── запись: segment 0, bus 0x40–0x7F, base 0xE400_0000
 └── запись: segment 1, bus 0x00–0x1F, base 0xE800_0000
```

Сегмент — не то же самое, что окно: в одном сегменте может быть
несколько окон, покрывающих разные диапазоны шин.

## Если MCFG нет

Тогда:

- платформа не поддерживает ECAM через ACPI;
- нужен доступ через порты `0xCF8`/`0xCFC`;
- либо параметры задаются в дереве устройств.

Драйвер должен явно сообщать об отсутствии окна, а не пытаться
угадать адрес.
