# 4.1. Обзор архитектуры

Драйвер строится из четырёх слоёв, каждый из которых можно
тестировать отдельно.

## Слои

```text
┌────────────────────────────────────────┐
│  Инициализация и перечисление          │
│  (платформенный код, список устройств) │
├────────────────────────────────────────┤
│  Доступ к конфигурации                 │
│  (read8/16/32, write8/16/32)           │
├────────────────────────────────────────┤
│  Окно ECAM                             │
│  (база, сегмент, диапазон шин, границы)│
├────────────────────────────────────────┤
│  Физическая память                     │
│  (отображение, volatile, барьеры)      │
└────────────────────────────────────────┘
```

## Почему так

| Слой | Зачем отделён |
|------|---------------|
| Память | Платформа даёт свой способ отображения |
| Окно | Позволяет поддержать несколько сегментов |
| Доступ | Единый API для всех устройств |
| Перечисление | Не зависит от конкретной платформы |

## Основные типы

```rust
pub struct Address {
    pub segment: u16,
    pub bus: u8,
    pub device: u8,
    pub function: u8,
}

pub struct EcamWindow {
    pub base: usize,
    pub segment: u16,
    pub start_bus: u8,
    pub end_bus: u8,
}

pub trait ConfigSpace {
    fn read8(&self, a: Address, off: u16) -> Result<u8, Error>;
    fn read16(&self, a: Address, off: u16) -> Result<u16, Error>;
    fn read32(&self, a: Address, off: u16) -> Result<u32, Error>;
    fn write8(&self, a: Address, off: u16, v: u8) -> Result<(), Error>;
    fn write16(&self, a: Address, off: u16, v: u16) -> Result<(), Error>;
    fn write32(&self, a: Address, off: u16, v: u32) -> Result<(), Error>;
}
```

## Ограничения `no_std`

| Ограничение | Следствие |
|-------------|-----------|
| Нет `alloc` | Списки устройств — фиксированного размера или через итераторы |
| Нет `std::error::Error` | Свой тип ошибки |
| Нет файлов | Конфигурация приходит от прошивки или из статики |
| Нет потоков | Блокировки — на примитивах платформы |

## Что должно быть в конфигурации

| Параметр | Источник |
|----------|----------|
| Базовый адрес окна | MCFG или дерево устройств |
| Номер сегмента | Там же |
| Диапазон шин | Там же |
| Окна памяти и ввода-вывода | Описание платформы |
| Номера прерываний | Контроллер прерываний или MSI |

## Порядок работы

```text
1. Получить описание окон от прошивки.
2. Отобразить окна в адресное пространство.
3. Создать объект ConfigSpace.
4. Просканировать шины из диапазона.
5. Распределить ресурсы.
6. Включить декодирование у устройств.
7. Передать список устройств остальной системе.
```

## Что не входит в драйвер

| Задача | Где решается |
|--------|--------------|
| Драйвер конкретного устройства | Отдельный модуль |
| Арбитраж прерываний | Контроллер прерываний |
| Управление питанием | Политика ОС |
| Горячая замена | Отдельная подсистема |
