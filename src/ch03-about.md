# 3.1. Общие сведения

В этой главе описан configuration space так, как его видит
программное обеспечение через окно ECAM.

## Правила доступа

| Правило | Пояснение |
|---------|-----------|
| Адрес | `base + (bus << 20) + (dev << 15) + (fn << 12) + offset` |
| Выравнивание | Кратно размеру доступа |
| Разрядность | 1, 2 или 4 байта |
| Границы | `offset + width <= 0x1000` |
| Порядок байтов | Little-endian |

## Обозначения

| Тип | Значение |
|-----|----------|
| `RO` | Только чтение |
| `RW` | Чтение и запись |
| `RC` | Чтение очищает |
| `RW1C` | Запись единицы очищает |
| `ROS` | Только чтение, защёлкивается |

## Значения после сброса

Не все регистры обнуляются. Часть сохраняет значения, часть
устанавливается аппаратурой:

| Регистр | После сброса |
|---------|--------------|
| Vendor ID | Постоянный |
| Device ID | Постоянный |
| Command | `0x0000` |
| Status | Зависит от возможностей |
| BAR | Размер и тип |
| Interrupt Line | `0x00` или значение от прошивки |

## Что читать первым

```text
0x00  Vendor ID   — есть ли функция
0x02  Device ID   — что это за функция
0x0E  Header Type — как читать остальное
0x0B  Class Code  — какой драйвер нужен
```

Только после этого имеет смысл разбирать BAR и возможности.

## Опасные регистры

Некоторые обращения имеют побочные эффекты:

| Регистр | Эффект |
|---------|--------|
| MSI-X Table | Чтение/запись меняет состояние прерываний |
| AER Status | Может очищаться при чтении |
| Power Management | Может изменить состояние устройства |

Поэтому «прочитать всё подряд для отладки» — не всегда безопасно.

## Соглашение об адресах

В таблицах главы смещения указаны относительно начала
configuration space функции. Полный адрес вычисляется
по формуле из раздела 2.2.
